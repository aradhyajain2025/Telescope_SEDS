# Validation, Testing, and Demonstration Plan (Zero Hardware)

If you need to prove that the work we've done so far is functional and correct—without waiting for the physical telescope to be built—you can run these three validation tests right on your laptop. 

This is perfect for a progress report or a live demonstration to a professor.

---

## Test 1: Firmware Configuration Validation
**Goal:** Prove that the tracking math and hardware configuration we generated for the ESP32 is valid and compiles without errors.

**Prerequisites:** 
- Download the Arduino IDE.
- Download the OnStep source code (from your `resources` folder or GitHub).
- Replace the default `Config.h` with the one generated by `python OnStep_Config_Template/config_calculator.py --apply` (patches the stock OnStep Config.h; the Arduino IDE needs the ESP32 board package, board "ESP32 Dev Module").

**Execution:**
1. Open `OnStep.ino` in the Arduino IDE.
2. Click the **Verify (Checkmark)** button in the top left.
3. The IDE will run the compiler against the code and our configuration.
4. **Validation:** If the console outputs "Done compiling" with no red errors, you have successfully proven that the mathematical tracking model (Steps/Degree) and hardware pinmap (CNC V3) are perfectly configured for the ESP32.

---

## Test 2: Software Communication (ASCOM) Validation
**Goal:** Prove that N.I.N.A. can communicate with telescope drivers via ASCOM.

**Prerequisites:** 
- N.I.N.A. and the ASCOM Platform must be installed.

**Execution:**
1. Open N.I.N.A.
2. Go to **Equipment > Telescope**.
3. In the dropdown, select **Telescope Simulator for .NET**.
4. Click the **Power Button (Connect)**.
5. **Validation:** A green success message will appear in the bottom right, and the current virtual coordinates (RA/Dec) will populate on the screen. You have just proven the ASCOM translation layer works.

---

## Test 3: The "Closed-Loop Tracking" Demonstration
**Goal:** Demonstrate the entire workflow: selecting a target, pointing the telescope, verifying the position via computer vision (Plate Solving), and issuing corrections. This proves our software stack replaces the old Python/OpenCV idea perfectly.

**Prerequisites:**
- N.I.N.A. connected to the Telescope Simulator (from Test 2).
- N.I.N.A. connected to the **Camera Simulator** (Equipment > Camera > Connect).
- ASTAP and the D80 star database installed.

**Execution (The Live Demo):**
1. In N.I.N.A., go to the **Sky Atlas** tab.
2. Search for `M42` (The Orion Nebula) and click **Set for Framing**.
3. The Framing Assistant will load an image of the nebula. 
4. Click the **Slew and Center** button in the bottom right.

**What to point out during the demo:**
- Watch the N.I.N.A. log at the bottom of the screen. 
- **Explain step 1:** N.I.N.A. commands the virtual telescope to slew to M42.
- **Explain step 2:** N.I.N.A. commands the virtual camera to take a 5-second exposure. 
- **Explain step 3:** N.I.N.A. hands that picture to ASTAP to "plate solve" it (matching the star pattern). 
- **Explain step 4:** ASTAP reports the exact coordinates back. If the telescope is slightly off-center, N.I.N.A. calculates the error and issues a tiny "Sync" command to perfectly center the target.

**Validation:** The sequence ends with a green success message: "Centering Successful." You have just demonstrated a fully automated, closed-loop GoTo tracking sequence with zero physical hardware!
