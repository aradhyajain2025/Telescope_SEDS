# Software <-> Hardware Interface (for the hardware team)

The laptop software assumes the mount behaves like an **OnStep 4.24s** controller. If it does, nothing in software changes.

## Connection
- USB serial, 9600 baud (OnStep default), **or** WiFi TCP port 9999 (needs an OnStep WiFi add-on/ESP).
- The software has been developed against `simulation/onstep_sim.py`, which speaks the same protocol.

## Commands the software uses (LX200 / OnStep)
| Command | Meaning | Reply |
|---|---|---|
| `:GR#` `:GD#` | read RA `HH:MM:SS`, Dec `sDD*MM:SS` | text + `#` |
| `:Sr…#` `:Sd…#` | set target RA / Dec | `1` |
| `:MS#` | goto target | `0` = started |
| `:CM#` | sync mount position to target (used after plate solving) | text |
| `:D#` | slewing? (`0x7F` in reply = yes) | |
| `:Te#` / `:Td#` | tracking on / off | `1` |
| `:Q#` | stop | none |
| `:GVP#` `:GVN#` | firmware name / version | |

## Firmware settings the software relies on
Generated by `OnStep_Config_Template/config_calculator.py`:
- `PINMAP CNC3`, `MOUNT_TYPE GEM`, `TRACK_AUTOSTART ON` (mount tracks on power-up)
- TMC2209, 64 microsteps, `AXIS1_STEPS_PER_DEGREE` from the real drive ratio
- RA only; Dec axis unused.

## What the hardware team must give us
1. Final drive ratio (motor pulley, driven gear, any extra stage) -> `--pulley --gear --extra-reduction`.
2. Platform travel limit in degrees (so we can set `AXIS1_LIMIT_MIN/MAX`).
3. Which direction the platform turns for +RA (set `AXIS1_DRIVER_REVERSE` if wrong).
4. COM port / IP address once flashed.

## Acceptance test (software side)
With tracking on and the scope on a star: image drift under ~30 arcsec in 10 min (the simulator shows ~20"). Without tracking the star drifts ~15 arcsec per second of time.
